01 — El problema

Hoy D-PAY solo cobra con un terminal Kozen

El POS móvil ya está en producción y emite DTE. El cobro con tarjeta, en cambio, depende de un Intent nativo de TUU Negocio en el Kozen P8 Neo. Sin ese hardware, no hay pago con tarjeta.

DEPENDENCIA

Un solo canal de cobro

Sin terminal TUU/Kozen, D-PAY no procesa crédito ni débito. El comercio queda limitado a efectivo u otro medio fuera de la app.

CAMPO LABORAL

Relevante para Informática

Es un problema real de arquitectura, integración con un PSP y modelado de transacciones: el tipo de trabajo de un ingeniero informático en fintech o retail.

RESTRICCIÓN

Sistema en producción

No se reescribe D-PAY. El cambio debe ser incremental: una capa nueva, sin tocar DTE ni el flujo de venta más de lo necesario.

07 — Stack técnico

Construimos sobre lo que ya existe

APP MÓVIL

React Native 0.75 + TypeScript

Zustand y MMKV para estado y persistencia. React Navigation en el flujo de venta.

NUEVO MÓDULO

PaymentGateway

Decide TUU o Webpay según el dispositivo. Un proveedor nuevo implementa el mismo contrato.

BACKEND

API Dtemite + DTE

Sin rediseñar emisión tributaria. Solo los ajustes estrictos que el nuevo medio de pago exija.

Sin Docker. El Capstone se construye sobre el POS React Native existente. TUU en Kozen es legado: no se reimplementa.
